## Parity-guard design quality

The new test (`coverage.test.ts:222-279`) is exceptionally well-designed:

1. **Realistic mock responses** — The DDB fixtures replicate the EXACT shape AWS Pricing API returns, including the region-prefixed `usagetype` AND the stable `group` attribute. Proves the decomposer correctly extracts via `group` when `usagetype` is region-prefixed.

2. **Mock dispatcher routes by filter** — Both S3 and DDB dispatchers examine `filters.some(f => f.Field === "group" && ...)` to route. If decomposer regressed to `usagetype`-filtering, mock falls through to `emptyData.success` and the unavailable assertion fires.

3. **Two-layer assertion** — (a) `usageBasedItems.filter(i => i.displayPrice === "unavailable")).toHaveLength(0)` (catches the original "unavailable" bug class), AND (b) `putItem?.unitPrice).not.toBeNull()` (catches a more subtle regression where item appears but no price extracted).

4. **End-to-end through `queryLineItemPrices`** — Not just unit-testing the decomposer's filter shape; the test exercises the full path: decomposer → query helper → mock dispatch → fixture → extractFirstTierPrice → unitPrice.
