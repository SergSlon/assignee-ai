# Reviewer: BOUNCE — qa (Quinn) — epic-108-close

## Verdict

**BOUNCE.** No issue surfaces in any single Epic 108 story when read in isolation, but the **combination** of Story 108-A-05 (noun-grouped command tree as a v1.0 API freeze) with the earlier-landed stories (108-A-03 `assignee discover`, plus user-facing strings in error catalogues and source files that pre-dated A-05) leaves the published surface **inconsistent with the runtime CLI**. The CLI ships `assignee infra plan ...` as the only valid invocation, but `docs/`, `README.md`, `docs/tutorials/getting-started.md`, `docs/how-to/quickstart.md`, ~95 user-facing source-code error strings, AND the `assignee dev discover` command's own command-category examples all still tell users to run `assignee plan ...`. Users following published docs hit `error: unknown command 'plan'` and exit 1 on every flat-path invocation. The CHANGELOG also carries a duplicated B-04 section (line 158 vs. line 150) that looks like a bad merge and should be reconciled before Paige authors the v1.0 entry (RR-9). There is also one pre-push hardening opportunity (`main-pre-rewrite-backup` + `refs/original/*` are not push-blocked) that should be added before RR-2 closure is treated as durable.

This is a Phase-4 follow-up bounce, not a recall of the merged commits. Recommended path: a **dedicated catch-up story (108-A-07 — noun-grouped path migration completion)** under the same epic, before flipping `RELEASE_CHECKLIST.md` to `[x]` on RR-9 and RR-11.
