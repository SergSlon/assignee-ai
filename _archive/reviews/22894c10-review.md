## Bounce-resolution audit

1. **Region scoping (BLOCKER) — REAL FIX.**
   `packages/core/src/utils/aws-resource-discovery/clients.ts:39-46,57-63,93-99,101-108`
   adds an optional `region?: string` to `createEc2Client`,
   `createRdsClient`, `createEcsClient`, `createElbClient`, forwarding
   `region ?? AWS_REGION` into the SDK constructor. Fetcher
   `packages/core/src/utils/aws-resource-discovery/vpc.ts:26-31` calls
   `createEc2Client(region)` (not the env-default form). Port
   `packages/core/src/services/resource-discovery-port.ts:100-115,
122-129` accepts `region` at factory time AND per-call
   `opts.region`, with `opts.region ?? region` as resolution order.
   The behavioural test
   `packages/core/src/services/resource-discovery-port.test.ts:162-167`
   stubs the SDK helper and asserts
   `expect(discoveryMocks.discoverVpcs).toHaveBeenCalledWith("eu-west-1")`
   — a region OVERRIDE test, not a port-surface test. Complementary
   `vpc.test.ts:113-118` asserts `createEC2Client` itself was called
   with `expect.objectContaining({ region: "eu-west-1" })`. End-to-end
   chain is observably exercised.

2. **Cache key region-namespacing (HIGH) — REAL FIX.**
   `vpc.ts:24-28`: `cacheKey = region ? \`${DiscoveryCacheKey.VPCS}:${region}\` : DiscoveryCacheKey.VPCS`.
Same pattern in `ecs.ts`, `elb.ts`, `rds-subnet-groups.ts`(per
diff). Fallback to bare key when region is undefined is acceptable
because the legacy callers (non-existing-discovery use sites) didn't
region-scope previously, so cache hits remain stable. The`:`separator collision risk (region containing`:`) is non-issue —
AWS region codes are `[a-z]{2}-[a-z]+-\d` strictly.

3. **`tagSubstringAutoSelect` first-match bug (HIGH) — REAL FIX.**
   `existing-resource-extractor.ts:111-158` rewrote the algorithm:
   tokenize ≥ 4-char words, drop `TAG_AUTOSELECT_STOPWORDS`
   (vpc/alb/nlb/elb/ecs/rds/lb + articles + "create/existing/new" etc.),
   build `uniqueMatchByWord: Map<word, candidate>` for every word that
   uniquely matches exactly one label, then **require convergence**:
   `if (matchedIds.size > 1) return null`. That is the correct shape —
   all unique-match words MUST point at the SAME candidate. The
   adversarial regression tests (`existing-resource-extractor.test.ts:
132-162` "rds in vpc" with no high-signal word → ambiguous;
   `:164-…` two distinct unique-match words → null because
   `matchedIds.size > 1`) exercise both Quinn's adversarial cases from
   the R1 review.

4. **Picker UX / ADR Decision 2 (HIGH) — REAL FIX.**
   The previous behaviour pushed all ambiguous candidates into
   `existing[]`, polluting graph state with N "Found existing X" lines.
   `existing-resource-extractor.ts:260-272` now drops ambiguous-kind
   candidates from `selected[]` and surfaces them in a new
   `ambiguous: Array<{kind, candidates}>` field. The advisory in
   `intent-parser/index.ts:343-362` enumerates ambiguous kinds with
   counts AND `details.ambiguousKinds[].candidateIds` so future picker
   wiring has the data ready. Variation B test
   (`existing-resource-extractor.test.ts:89-107`) asserts
   `result.existing.toHaveLength(0)` and
   `result.ambiguous[0].candidates.toHaveLength(2)` — the exact
   graph-state-hygiene contract. Mixed-kind case (single-match A +
   ambiguous B) is implicitly covered by the per-kind `byKind` loop,
   though a dedicated mixed-kind test would harden it (paydown note).

5. **Pagination (MED) — REAL FIX.**
   `vpc.ts:32-46` loops over `NextToken`. The pagination test
   `vpc.test.ts:120-150` chains
   `mockSend.mockResolvedValueOnce({ ...page1, NextToken: "tok-2" })
.mockResolvedValueOnce({ ...page2 /* no NextToken */ })`,
   then asserts BOTH VPCs appear in result AND

   ELB `Marker`/`NextMarker`, ECS `NextToken` + per-page Describe-100)
   trusted from diff stat; mirror tests likely exist in the per-file
   `*.test.ts` (sampled vpc only at line budget).

6. **runId threading (MED) — REAL FIX.**
   `productionResourceDiscoveryPort(region, runId)` accepts runId,
   `intent-parser/index.ts:328` passes `state.runId`. The
   `DISCOVERY_FAILURE` log line in `resource-discovery-port.ts:118-123`

   `existing-resource-extractor.ts:225-232` (`runId: "discovery"`) is
   only reachable on belt-and-suspenders import-failure throws, not
   on the SDK-error path that R1 flagged — acceptable.

7. **Destroy mirror test (structural) — BEHAVIOURAL, not shape-only.**
   `apps/cli/src/commands/destroy/bulk-action.test.ts:1153-1262`

## Adversarial findings (new)

- **LOW**: `existing-resource-extractor.ts:225` belt-and-suspenders log
  line still uses `runId: "discovery"` literal — only reachable on
  unexpected throws (e.g. import failure), so practically harmless,
  but inconsistent with the R2 thesis of "always real runId". Trivial
  fix: thread runId into `extractExisting` signature. Defer-OK.
- **LOW**: Mixed-kind ambiguity (e.g. one unique VPC + ambiguous ECS
  clusters) is implicitly covered by the per-kind loop but lacks an
  explicit unit test. Adding one would close the test-coverage gap on
  the most likely real-world picker scenario. Defer-OK.
- **LOW**: `tagSubstringAutoSelect` JSDoc references the "longest such
  word" tie-breaker rule but the implementation just takes the first
  Map entry (insertion order). Code is correct (single matchedId ⇒
  one candidate regardless), but the doc/code divergence is a
  maintenance hazard. Doc-only fix.
