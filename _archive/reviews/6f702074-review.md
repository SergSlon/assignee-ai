## Skip-rationale soundness (review scope item 1)

**Sound.** The skipped test scenario is:

1. `appendAuditRecord` once (file lands at 0o600 via `fs.chmod`).
2. `fsSync.chmodSync(logFile, 0o644)` — simulate operator widening.
3. **Sanity-check** `expect(fsSync.statSync(logFile).mode & 0o777).toBe(0o644)`.
4. `appendAuditRecord` again — production code re-issues
   `fs.chmod(logFile, 0o600)` (audit-log.ts:171).
5. Assert mode is back to 0o600.

On Windows/NTFS, `chmodSync` only toggles the read-only bit; the
group/other bits don't exist in NTFS perms. So:

- Step 3 sees `0o666 = 438` (NTFS default for a writable file), not
  `0o644 = 420`. Failure manifests as `expected 438 to be 420` —
  exactly what `--log-failed` shows at `:596:51` and `:611:51`.
- Step 4's production chmod is also a no-op on NTFS.
- Step 5 would also be 0o666 — the re-enforcement is unobservable
  because there was nothing to widen in the first place.

The behaviour under test is **inherently a POSIX-only property**
(SEC-006 chmod re-enforcement); there is no Windows-side
behaviour-loss from skipping. Sanity-only sub-assertion guarding
(option (b) in the task: `if (process.platform !== "win32") expect(...)`
around line 596 only) would still leave the line-610 re-enforcement
assertion broken — same `438 to be 420` outcome at step 5. Whole-test
skip is the correct grain.

`{ skip: process.platform === "win32" }` (options-object form, 3-arg
overload) vs `it.skipIf(process.platform === "win32")` (modifier
form): both work in vitest 3.2.4. The chosen form **matches the
pre-existing line-173 skip in the same file verbatim**, which is the
right consistency call. Backlog doc's "fix is `it.skipIf(...)`" line
is a minor cosmetic drift from the implementation but doesn't affect
correctness (LOW finding below).

## Findings

### LOW-1: Backlog doc says `it.skipIf(...)` but fix uses `{ skip: ... }`

Lines in `_backlog/cross-platform-windows-residual-failures.md`
recommend "fix is `it.skipIf(process.platform === "win32")`" twice
(diagnosis paragraph + summary). Actual implementation uses
`{ skip: process.platform === "win32" }` (3-arg options-object
form), which matches line-173 precedent and is functionally
equivalent in vitest 3.2.4.

**Impact:** Cosmetic. Future grep for `it.skipIf` in the codebase
will miss these two new skips. Recommend either (a) update the
backlog diagnosis paragraph to say "options-object form, mirroring
line 173" or (b) leave it — the doc is point-in-time enumeration,
not a binding spec. Either is fine; prefer (a) for grep-discoverability.

### LOW-2: NOTICE staleness on Windows job not captured in backlog

Windows job 76927964651 ALSO logs `[generate-notice] --check FAILED:
NOTICE files are stale` (THIRD-PARTY-NOTICES.md), downgraded to a
workflow warning. Doc focuses on test failures only. Out of scope
for THIS PR but worth a separate backlog line so it doesn't
disappear before the Phase C dispatch flips experimental:false (a
warning on a non-experimental Windows job is still noise we'd
want clean).

### LOW-3: Doc says apps/cli "154 test files" — actually 122 passed + 32 skipped

Minor counting drift in the per-package table. Doc reads "154" in
the test-files column; the gh log shows `122 passed | 32 skipped
(154)`. The 154 is the TOTAL (passed+skipped), so the doc is right
on totals but ambiguous on "files vs files-executed". Not worth
fixing — comprehension is preserved.
