### Excerpt added (reproduced here for trackability)

```markdown
## Stage review-evidence files BEFORE authoring the commit body

When closing a story that cites a Quinn review file (`_archive/reviews/<short-sha>-review.md`),
the evidence file MUST be added to the git index BEFORE the commit body is
authored, otherwise `reviewer-evidence-audit` (CI job) fails with
`missing-file: evidence file missing: <name>-review.md` after the PR is opened.

Workflow (Bob retro action #2 from Epic 108 — caught us on commit `8fa85638` →
amended to `3aae363a` after CI bounce):

1. Quinn writes the review to `_archive/reviews/<short-sha>-review.md` on disk.
2. Coordinator `git add _archive/reviews/<short-sha>-review.md` BEFORE running
   `git commit -m "...Reviewer: ACCEPT — ... — see _archive/reviews/<short-sha>-review.md"`.
3. The pre-push hook + CI audit script both validate that the cited filename
   exists in the commit's tree. Staging is the only way to put it there.

If the citation+file mismatch is caught at CI (post-push):

- Amend the commit to add the file: `git add <file> && git commit --amend --no-edit && git push --force-with-lease`.
- This is the rare case where amend-after-push is sanctioned (the citation
  text doesn't need to change, only the file membership in the tree).

Common failure modes:

- Coordinator runs Quinn dispatch → reads the verdict → commits with the ACCEPT
  citation → push → CI catches the missing file.
- Worker authors the commit body before Quinn writes the review; same outcome.

The fix is to make staging the evidence file step 1 of the commit ritual, not
an afterthought.
```

This closes Bob's retro action item #2.
